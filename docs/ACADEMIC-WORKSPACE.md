# v4 學期、開課計劃及年度工作量

## 由舊版本開始

1. 在舊版匯出JSON。將v4完整ZIP解壓，開啟`index.html`，保留所有程式檔及vendor資料夾。
2. 用「完整還原」讀取備份，再於「學期設定」補上`2026/2027`一類學年及上／下學期。原課節、時間、併班、人數、假期等保留。
3. 舊課節會形成已建立的開課基線，不能據此知道尚未輸入的預計科目；到「本學期開課計劃」勾選其餘預計開設科。
4. 若有另一個學期的舊JSON，用「學期與全年時數 → 匯入單學期」，確認來源學年及上／下學期，加入後切換核對。同一學年及學期只可有一份，避免全年重複計算。

「完整還原」會取代整個工作簿（所有學期及年度安排），有明確提示及撤銷；「匯入單學期」則保留現有學期。多學期檔不能當成單學期匯入。

## 勾選本學期開課

先選BAE、MFI、MFT或DFI課程，再勾選本學期的科目，加入計劃後選取要建立的科。可以一次處理多個年級；各科分別填年級、A–Z班級範圍、每班每週目標節次、教師與考核形式。學分／必選修帶入但可改，課室及人數可留空。

- 科目下拉先按課程篩選，再按學期／年級／方向縮小。共同必修仍出現在適用方向。
- 科目庫的「適用課程」可以選多個，供通識或共用科目使用。未提供的碩博正式科目表不作推斷；可手動輸入新選修，也可編輯科目庫分類。過往學期已有但未建專用預設的科目，亦可作選單參考。
- 手動建立的新編號會保存為科目預設及本學期計劃；未填編號的臨時科目仍可按名稱建立計劃。
- 每週節次是每班目標總數。A–C各2節需要6個拼圖；已有5個則補1個，重按不增加重複拼圖。要增加每週節次時提高目標數；已有不同教師的班級須先核對，不能無提示混入。
- 「已建齊」不是「已排好」。計劃有10科、其中6科建齊其設定班級與節次，即60%；其餘40%包含未建及部分建立。已建拼圖可仍在待排池，已排數另列。
- 缺少C班的拼圖不能由A班多出的拼圖補算。刪除拼圖會使該科重回部分建立，方便補建。
- 「移出計劃」只移除計劃項目，保留拼圖。建立、補建、移出及學期切換均可撤銷／重做。

## 保留不同學期

新建學期後，舊學期完整保留。頂部下拉或學期清單可以切換；每個學期有獨立課表、待排、計劃、教室、人數、限制、假期、補課跟進及併班例外。科目庫共用，明確修改考核只同步目前學期的同編號科目，不改歷史課表。

新學期可選擇帶入教室清單；課節、假期、禁排及特殊併班例外由空白開始，避免把本學期罕見的BAE406／411安排永久沿用。原學期併班仍保留。上／下學期由管理者明確指定，不根據月份猜測舊備份。

完成核對後可「確認核算」。系統要求學年及上／下學期明確、開課計劃建齊、沒有待排節次，且確認時沒有已知排課衝突。確認後先作檢視與匯出，修改須重新開放；這是管理者確認的名義工作量，並不是系統證明實際已完成授課。

## 全年時數與翌年差額

按同名教師及學年合計本院兩學期。每個學期使用自己的教學週數／學時分鐘；考試科即使常規上課14週，核算仍含考試週，通常15週。併班按各班相加，外院課只作排課避撞，不進入本院教師時數。

| 指標 | 計法或含義 |
| --- | --- |
| 上／下學期已排 | 已放入時間格的名義教學時數 |
| 待排 | 已建立、尚未放入時間格的名義時數 |
| 全年預計 | 已排＋待排；未建立課節不會猜測時數 |
| 年度標準目標 | 預設360，按學年設定，教師可有個別值 |
| 結轉調整 | 管理者明確採用的正／負調整，預設0 |
| 本年目標 | 標準目標＋已確認結轉調整，不可負數 |
| 尚可分配 | 本年目標－已排－待排；負數表示預計超出 |
| 距已排目標 | 本年目標－已排；有待排時不等於實際欠課 |

例：上學期5班、每班2節×75分鐘×15週÷50分鐘＝225學時。目標360，尚可安排135，按相同口徑相當於3班。不是每門課一律45，仍依實際班數、每週節次與核算參數計算。

只有上學年兩學期都「已確認核算」，才會給下學年差額參考；新學年工作畫面會提示相關教師，可跳到年度建議，也可暫時關閉提示。上年目標360、已排405，本年可參考315；上年315，本年可參考405。這不是自動改變教師負擔或學院政策；在「目標／結轉」可填入該參考值，補充備註後明確儲存。

例如確認採用上年多排45的調整：本年標準360、結轉-45，目標315。本年排足315，下一年差額為0，不會再把同一45反覆抵扣。重新開放上年任一學期後，未確認的差額暫停作新參考；已儲存的管理者調整保留，可自行核對更新。

同名姓名必須一致；同名不同人請用可區分的教師名稱。科目庫／計劃資料不是學生最終選課名單，亦不推斷學生個別跨班衝突。

## 本機資料、備份及容量

支援時使用IndexedDB本機資料庫，完整工作簿不再塞入localStorage；後者只留修訂號標記以偵測另一視窗更新。首次修改舊資料時會儲存到資料庫。不能使用時可回退原儲存方式；頁面顯示模式、儲存中／已儲存／未儲存狀態。儲存失敗會提示匯出完整備份，不會靜默宣稱成功。

瀏覽器資料不是校內共享資料庫；程式沒有上傳排課資料、外部資料API或即時同步。完整JSON仍應存到經批准的校內位置。清除瀏覽器網站資料、換電腦／瀏覽器、換開啟位置或重新解壓版本前，請先備份並在新位置還原。私人瀏覽的資料亦不應作唯一保存來源。

現版本最多40個其他學期、每學期10000個課節、所有學期合計100000課節；實際瀏覽器容量及效能仍依電腦而定。只保留一位主編輯者，同機另一視窗會用版本檢查防止舊資料覆寫。

## 給開發者：格式9與下一階段

根欄位保留目前學期的舊欄位，新增：

| 欄位 | 用途 |
| --- | --- |
| `termInfo` | 穩定學期ID、學年、上／下學期、是否經確認核算 |
| `offeringPlan` | 科目／課程／年級及各班每週目標節次，獨立於實際拼圖 |
| `archives` | 其他學期快照，不包含巢狀歷史、共用科目庫或年度設定 |
| `workload.yearTargets` | 各學年一般目標 |
| `workload.teacherTargets` | 教師年度標準目標、明確結轉及備註 |
| `catalog[].programs` | 適用課程代碼，可多個；舊編號可依已知前綴補入 |

單學期匯入以新學期ID加入，不覆寫已有年／學期；缺少的科目預設及年度設定可補入，已有共用設定保留。歷史課節ID可以在不同學期重用，但學期內必須唯一，後續介接須以「學期ID＋課節ID」作完整識別。

下一階段待用戶驗收後再做考試系統資料接口：先利用學期ID、課程、科目編號、考核形式、班級、教師、課室及人數等欄位預填，減少重複輸入；考試事件須獨立表示期中／期末，不能因期末是報告／論文就排除期中考試。現版本未建立考試、座位表或簽到表，也未接通其他後台。
